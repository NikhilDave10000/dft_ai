Command	Options	Description
set_atpg	[-abort_limit ]	"Controls ATPG search effort per fault. Defines how many backtracks (aborted decisions) are allowed. 
Working : ATPG tries to generate a pattern by making assumptions, setting inputs and scan chain values, and determining whether controllability and observability can be attained.
If assumption fails → backtrack (abort)
Process repeats until: Pattern is found , Abort limit is reached . 
Use default (10) for most designs , Increase for hard-to-detect faults
Avoid very high values → runtime increases"
	[-capture_cycle d]	"Controls Fast-Sequential ATPG effort level. 
Values: 0 → Basic Scan (combinational, default)
2–10 → Enables Fast-Sequential ATPG
Recommended start: 4 (increase gradually to improve coverage)
Higher value → better coverage but longer runtime.  Required for system_clock mode (d ≥ 2)
d = 1 →  invalid
If run_atpg -auto_compress → sets capture_cycles = 2 by default. If d > 2 :
First runs 2-cycle ATPG (easy faults)
Then higher cycles for remaining faults. 
Guideline: Full scan → 2 is enough
Partial scan / memory → use >2."
		
Basic Scan Mode : 		"Default ATPG mode
Uses combinational ATPG
Tests flip-flops individually (ignores sequential behavior)
Scan chains bypass normal logic → fast testing & easy debug"

Full_Sequential  Mode :		"Supports unlimited capture cycles between scan load & unload
Provides highest fault coverage, especially for partial-scan designs
Does not require full controllability of clocks/resets at primary inputs
Full-Sequential with Transition Faults - Not controlled by:

If you want to generate only last-shift launch patterns and avoid all system-clock launch patterns, you should be aware that there is no way to guarantee that you will get only last-shift launch patterns with the Full-Sequential engine. Even those last-shift launch patterns that it might generate will not be identical in form to those generated by the Basic-Scan ATPG engine"
